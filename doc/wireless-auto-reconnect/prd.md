# 无线设备自动重连 PRD

状态：设计稿，尚未实现。日期：2026-09-14。

适用产品：AdbPilot 桌面 GUI。技术设计见 [技术方案](technical-design.md)。

## 1. 背景与目标

用户已连接过一台手机，之后手机 IP 或无线调试端口变化，希望再次打开 AdbPilot 或手机回到网络时自动恢复连接，不必重新查地址、输端口或扫码。

当前程序具备手动连接、配对码与二维码配对、mDNS 服务查询、设备轮询，以及基于 `ro.serialno` 的在线设备去重；缺少持久化的历史设备身份和完整的自动重连调度。IP 地址、ADB 连接 serial 和物理设备身份尚未在 GUI 中独立管理。

本需求的成功标准是：在已授权、网络可达、手机无线调试开启的条件下，同一台手机换地址后重新显示为原来的设备，恢复选择或锁定关系，并给出可追踪的状态日志。

## 2. 用户与场景

| 场景 | 期望结果 |
| --- | --- |
| 手机重新连接 Wi-Fi，DHCP 分配新 IP | 自动发现新地址并恢复原设备 |
| 手机无线调试重新开启，端口变化 | 更新连接端口，不要求重复配对 |
| 关闭后重新打开 AdbPilot | 读取历史设备并恢复连接 |
| 电脑休眠、网络断开后恢复 | 后台重新发现，界面可继续操作 |
| 两台同型号手机同时在线 | 按设备身份分别展示，不按型号合并 |
| 同一台手机有 IP、mDNS 或 USB 多条连接 | 同一逻辑设备仅计数一次 |
| 原 IP 被另一台手机占用 | 不替换原设备，不把业务操作发给另一台手机 |
| 用户主动断开 | 暂停 AdbPilot 对该设备的自动重连 |

## 3. 范围与前提

首期覆盖 Windows GUI，核心逻辑保持跨平台；macOS/Linux 的实际效果需各平台验证。主要支持 Android 11+ 手机的无线调试 TLS 连接。手机与电脑需要网络互通，自动发现依赖 mDNS 可用。

ADB 本身已提供已配对设备自动连接能力，应用先接收其结果，再为已记住的设备提供发现、验证、重试和状态管理。[Android 官方 ADB 指南](https://developer.android.com/tools/adb)

首期不包含：跨公网连接、手机离线时远程开启无线调试、无授权配对、子网或全端口扫描、开机后台服务、自动重放安装与 Shell 操作、重建 ADB 凭据。旧版 `adb tcpip` 的 IP 变化自动恢复不作承诺，保留手动连接。

“USB 连接过”不等于完成无线配对。只有 USB 历史的手机可以被识别，但需要用户先完成无线连接或配对才能启用本功能。

## 4. 功能需求

### 4.1 记住设备

- 经 AdbPilot 手动连接、配对后首次达到可用状态且完成身份读取，自动保存该无线设备，默认开启自动重连。
- 已由其他 ADB 客户端连接的设备正常展示，但不自动加入重连历史；用户可勾选“自动重连”加入。
- 保存设备名称、硬件序列号、已验证的服务实例、最近成功地址和时间；不保存配对码、二维码密码或私钥。
- 身份为空、未知或存在冲突时，允许当前连接使用，但显示“身份未确认”，不自动关联历史设备。
- 软件升级不将旧 IP 输入框直接迁移成可信设备；首次观察到可用设备后按上述规则建立记录。

### 4.2 自动发现与恢复

- 应用启动、已记住设备掉线、发现新地址和用户点击“立即重连”时触发恢复流程。
- 优先接收 ADB 已建立的连接；再从 mDNS 完整快照中查找目标设备，不能只等待新增服务事件。
- 对匹配候选地址进行有界连接，连接后再次验证设备身份；通过验证后才更新历史地址和恢复选择、锁定。
- mDNS 暂不可用时，可有限尝试最近成功地址；失败进入退避，不持续阻塞界面。
- 多台历史设备独立恢复；单台超时不能阻塞其他设备全部进度。
- 只因网络失败或 mDNS 列表为空，不判定配对失效。明确授权失败时提示检查授权或重新配对。

### 4.3 设备列表与历史记录

- “在线设备”和“历史设备”分开显示，在线计数只统计已确认可用的逻辑设备。
- 在线设备行展示名称、连接方式、当前地址和状态；多条连接聚合到同一设备，详情可查看各连接。
- 历史设备展示上次连接时间、最近地址、自动重连开关及当前重连状态。
- 历史记录不因一次连接失败消失；设备状态变化原位更新，避免新增一条同名设备。
- 当前选择或锁定跟随逻辑设备身份。恢复后可以执行新操作，但已经失败或中断的任务不自动重放。

### 4.4 用户控制

| 操作 | 行为 |
| --- | --- |
| 自动重连开关 | 每台设备独立设置，跨应用重启保存；关闭即停止应用重试 |
| 立即重连 | 发起一次完整恢复尝试，不隐式改变自动重连开关 |
| 断开 | 对选中设备的已知无线连接执行断开，并持久化暂停自动重连；USB 不受影响 |
| 恢复自动重连 | 清除暂停状态，立即触发发现 |
| 忘记记录 | 删除本地历史和待执行重连；当前连接可继续显示 |
| 扫码／配对码配对 | 保留现有入口，明确授权失败时可手动重新配对 |

暂停只约束 AdbPilot 主动发起的连接。共享 ADB server 或 Android Studio 仍可能连接该手机，此时显示真实在线状态，同时保留“自动重连已暂停”。不循环断开其他客户端建立的连接。

“忘记记录”不等于解除手机授权，也不保证设备不再被 ADB 自动发现。彻底解除配对需在手机中忘记此电脑。

### 4.5 状态与日志

设备状态：在线、等待发现、连接中、验证中、等待重试、需授权、已暂停、身份冲突。配对完成但尚未连接时不得显示“在线”。

输出框记录每轮重连开始与结束、触发原因、发现地址、地址变化、验证结果、失败原因、下次重试时间，以及暂停／恢复／忘记事件。每轮有独立标识，便于多设备日志关联。

示例：

```text
[10:20:00] 手机 A：开始自动重连，原因=应用启动
[10:20:02] 手机 A：发现新地址 192.168.1.80:39621
[10:20:03] 手机 A：正在连接并确认设备身份
[10:20:04] 手机 A：重连完成，地址已更新
```

后台常见网络失败不弹阻塞对话框；状态区给出原因，输出框保留诊断。相同错误合并计数，状态变化与最终结果必须保留。提供保存重连日志入口，导出默认遮蔽完整序列号与地址，不导出凭据。

## 5. 异常与边界

| 条件 | 用户可见结果 |
| --- | --- |
| mDNS 服务为空或查询失败 | 等待发现／等待重试；提示检查无线调试及网络，不断言设备已取消配对 |
| 手机关闭无线调试、离线或电脑切换网络 | 保留历史记录，按退避重试；条件恢复后继续发现 |
| 连接输出成功，但列表仍为 offline | 继续等待或进入重试，不宣告恢复成功 |
| 配对授权被撤销 | 已确认授权错误时显示“需授权”，停止高频连接并保留配对入口 |
| 序列号读取失败或多台设备身份冲突 | 保留原历史记录，显示未确认／冲突，不自动绑定 |
| ADB 路径变化或用户重启 server | 废弃旧任务结果，重新读取连接状态 |
| 历史文件损坏或无法写入 | 当前连接仍可使用，显示“历史记录未保存”并记录具体错误 |
| QR 配对期间发现其他历史设备 | 不把历史设备恢复当作本次扫码成功，不覆盖二维码状态 |

IP 和端口都会变化；随机 MAC 不是设备身份依据，也不能单独据此判断发现失败。即使使用固定 IP，端口变化仍需要发现或人工更新。

## 6. 验收标准

以下时延是设计目标，不代表当前已测得结果。基准环境：1 至 5 台设备，局域网正常，配对有效，mDNS 可发现，设备 shell 可用。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A1 | 单台手机换 IP 和端口后重新发布服务 | 在服务持续可发现后 30 秒内恢复；原历史记录更新，无重复在线行 |
| A2 | 同一手机同时通过 IP、mDNS、USB 连接 | 确认身份后在线计数为 1，详情保留可用连接 |
| A3 | 两台同型号手机同时恢复 | 分别关联原记录，锁定目标不互换；进行 20 轮回归无误关联 |
| A4 | 旧 IP 被另一台已授权手机使用 | 身份不符即拒绝绑定，不发送任何业务命令 |
| A5 | 退出再启动应用、休眠恢复 | 自动读取启用记录并恢复；暂停记录不被应用主动重连 |
| A6 | mDNS 禁用或网络隔离 10 分钟 | 界面可操作，无循环弹窗；日志有限、重试有界，保留手动连接 |
| A7 | 配对撤销、offline、空身份分别注入 | 不误报在线或误更新身份；原因和退出状态可追踪 |
| A8 | 连接中暂停、忘记、切换 ADB 路径 | 旧结果不恢复已删除记录，不改变新会话状态 |
| A9 | 锁定手机换地址，另一台仍在线 | 锁定跟随原手机；未恢复前业务操作明确失败，不回退到另一台 |
| A10 | 一台扫描二维码，另一台历史设备上线 | 两套日志可区分，QR 完成判据不受历史设备上线干扰 |
| A11 | 外部 ADB 在暂停后连接设备 | 显示实际在线且保留暂停标记，应用不争抢或循环断开 |
| A12 | 历史写入失败及日志导出 | 连接仍可用；保存失败可见；导出包含阶段结果且无密码、私钥 |

## 7. 交付顺序

1. 建立设备身份与历史记录，保留原有手动连接流程。
2. 实现发现、验证、重试和取消，接入后台设备轮询。
3. 接入历史列表、开关、锁定恢复、诊断导出和 QR 会话隔离。
4. 完成自动化用例与 Windows 真机验收，再扩展平台验证。

首期默认采用本文的自动记住与暂停策略；不新增遥测，不承诺手机端条件不满足时也能自动恢复。
