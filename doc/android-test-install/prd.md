# AdbPilot AndroidTest APK 无人值守安装 PRD

状态为需求草案。日期为 2026-11-11。依据见 [调研文档](research.md)。

## 1. 用户目标

开发和 QA 在专用 Android 真机上执行插桩测试。给定目标设备和测试 APK 后，AdbPilot 能安装 `testOnly` APK，并在已支持的机型上处理首次安装确认。安装成功后，现有测试脚本可继续执行 `am instrument`。用户可以从命令结果判断是安装成功、需要人工处理，还是安装失败。

## 2. 首期范围

覆盖 AdbPilot 的单 APK 安装入口，包括桌面 GUI、普通 CLI 和供自动化调用的 AI CLI。支持已完成 ADB 授权、屏幕可交互的专用测试设备。先验证至少一款能够稳定触发首次安装确认的真机，按机型、系统构建和连接方式记录支持范围。模拟器用于验证标准安装路径。

首次 ADB 授权、设备解锁、厂商设置和企业设备管理由设备初始化流程处理。构建 APK、编排测试套件、分包安装和修改系统安装策略超出本期范围。

## 3. 功能需求

| 编号 | 需求 | 用户可观察的行为 |
| --- | --- | --- |
| R1 | 安装测试 APK | GUI 提供「允许测试 APK」选项，CLI 和 AI CLI 提供等效参数。启用后本次安装传 `-t`，并沿用用户选择的覆盖安装等参数。遇到 `INSTALL_FAILED_TEST_ONLY` 时提示开启该选项。 |
| R2 | 按次启用自动确认 | 在同一安装入口提供独立的「自动确认安装弹窗」选项，默认关闭。启用时将监听限定在本次安装和选定设备，首次安装与覆盖安装均可使用。自动化调用明确指定目标序列号。 |
| R3 | 确认当前安装 | 只有在本次安装等待期间，识别到受支持的安装器窗口、已验证的安装按钮以及可关联到当前 APK 的目标信息时，才执行点击。界面仅有通用「允许」文字、目标身份不明确、出现其他授权或安全提示时，进入人工处理。 |
| R4 | 报告真实结果 | 以 ADB 安装结果判定成功。输出包含目标设备、APK、安装阶段、是否尝试自动确认、ADB 返回的错误以及所需操作。没有弹窗的成功安装照常完成。CLI 失败使用非零退出码，AI CLI 返回结构化结果，GUI 保持可操作。 |
| R5 | 限定监听生命周期 | 安装完成、超时、取消、断开或异常时停止监听。超时或取消时若设备端结果未知，明确提示并允许重新查询。启用自动确认时，同一物理设备上的 AdbPilot 安装任务串行，不同设备的任务彼此隔离。 |
| R6 | 保留已有安装状态 | 覆盖更新沿用现有签名与数据保留行为。签名不兼容、降级受限、权限不足或自动确认失败时反馈原始错误，应用已有数据保留，卸载由用户另行发起。 |

## 4. 交付顺序

1. 将 `-t` 贯通三个安装入口，验证常规 APK 和测试 APK 的参数与结果。
2. 在实际触发弹窗的真机上验证安装器窗口识别、目标 APK 关联和点击结果，记录机型、ROM、系统构建和连接方式。
3. 在验证通过的配置上接入按次自动确认，覆盖无弹窗、无法识别、超时、取消和设备断开。若真机无法稳定识别或操作安装窗口，先交付测试 APK 安装选项，并保留人工确认和诊断信息。

## 5. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | AOSP 模拟器首次安装 `testOnly` APK | 三个入口均可启用 `-t`，测试 APK 安装成功，`pm list instrumentation` 可见目标 runner，`am instrument -w` 能启动并完成约定的冒烟测试。 |
| A2 | 已验证真机首次安装时出现确认弹窗 | 每轮以测试 APK 未安装为起点，开启自动确认连续完成 10 轮。每轮 ADB 返回成功，目标 runner 可执行，期间无需点手机。10 轮为验收目标，当前尚无实测数据。 |
| A3 | 更新已安装测试包 | 使用相同包名和兼容签名覆盖更新，数据按现有覆盖安装行为保留。没有弹窗时不触发任何点击。 |
| A4 | 默认关闭，或出现其他窗口 | 默认安装不启动监听。开启后遇到无法关联的安装弹窗、RSA 授权提示或其他应用的「允许」按钮时，无自动点击，安装任务给出人工处理提示或明确失败原因。 |
| A5 | 安装超时、取消或设备断开 | 监听及时结束，后续弹窗不被点击，输出能区分失败与结果未知，GUI 不被阻塞。 |
| A6 | 多设备和同一设备并发 | 两台设备同时安装时，各任务只操作指定设备。同一物理设备的两个安装任务不会同时触发自动确认。 |
| A7 | 签名冲突、厂商拦截和普通 APK 回归 | 保留原有包及数据，输出可追踪的失败原因。普通 APK 保持原有安装参数和行为。 |

待验证项为目标真机、弹窗归属、窗口是否暴露可用控件，以及首次安装和覆盖安装是否表现一致。发布支持列表前应将这些结果关联到对应验收记录。
