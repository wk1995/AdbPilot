# 无线调试卡顿诊断可行性分析

建议在 AdbPilot 内扩展，先做同一台手机的真机对照，再用现有 CLI 做按需采集。AdbPilot 已有 ADB 路径解析、设备选择、命令超时、连接事件和文件导出。手机端的帧与 CPU 调度分析可以交给 Perfetto。若未来需要脱离 ADB 长期采集、发布独立的 Android 采集端，或服务于与 AdbPilot 无关的设备和用户，再评估拆仓。

本次依据 `master` 的 `78b02ab` 做源码分析，尚无真机采样数据，卡顿原因仍待复现。

## 当前代码里值得验证的路径

- [GUI 设备监听](../../adbpilot/gui.py#L1799) 每 3 秒尝试刷新设备列表。`adb devices -l` 查询主机侧 ADB server。只有当列表里至少有两个在线传输时，[设备去重](../../adbpilot/client.py#L154) 才逐个执行设备端 `getprop ro.serialno`。同一台手机通过 USB 和 Wi-Fi 同时出现，也会进入这个分支。可先对照单一无线传输和双传输场景，并记录每轮查询的数量与耗时。
- [mDNS 自动恢复](../../adbpilot/gui.py#L1827) 在设备列表为空且未在进行配对等操作时才进入恢复检查。它更适合关联掉线或重连时刻。设备稳定在线时，优先验证其他路径。
- [实时 logcat](../../adbpilot/client.py#L850)、[文件传输和录屏](../../adbpilot/client.py#L367)、APK 安装都可作为独立负载变量。录屏会在设备上编码，并在结束后拉取文件，两个阶段可分别记录。GUI 的 [logcat 读取](../../adbpilot/gui.py#L2514) 是按需执行的日志快照。
- [连接历史](../../adbpilot/client.py#L958) 可以提供出现、离线和状态变化的时间点。当前缺少手机帧时间、ADB 命令耗时和同时发生的操作记录，需要新增诊断数据才能判断这些事件和卡顿是否重合。

## 真机对照

在同一台手机上手动重复同一个动作，例如在目标 App 内滚动同一列表。如果桌面或系统设置也卡，另用同一个系统页面重复一遍。固定 Wi-Fi、刷新率和前台应用，尽量匹配电量、温度、充电状态。每组先做 3 轮，每轮 30–60 秒，交替运行各组，记录卡顿出现的时刻。手机本地 System Tracing 可在无线调试关闭时记录基线。各组用同一组 trace 配置，采完再导出，并补做一轮无 trace 的复现，检查采集本身的影响。[Android 真机系统跟踪](https://developer.android.com/topic/performance/tracing/on-device)

| 对照组 | 设置 | 验证问题 |
| --- | --- | --- |
| A | Wi-Fi 保持连接，关闭无线调试，无 USB | 手机本身是否已经掉帧 |
| B | 开启无线调试，确认没有主机连入，无 USB | 开启无线调试后的表现有无变化 |
| C | 普通 `adb` 建立无线连接后空闲，AdbPilot 和 Android Studio 关闭 | 无线 ADB 会话空闲时的表现有无变化 |
| D | 保持同一无线连接，打开 AdbPilot GUI 空闲 | GUI 设备监听是否和卡顿同时出现 |
| E | 在 D 基础上，一次只加一种实际调试负载，如实时 logcat、APK 安装、文件传输或录屏 | 哪个操作和帧时间或命令耗时变化同时发生 |

若仅双传输时复现，在相同 USB 接线状态下比较单传输与双传输，并记录去重查询次数。USB 也可作为命令耗时的额外参照，需标注充电与温度差异。

- **手机画面卡**。优先查看目标应用或系统界面的实际帧时间与超期帧，再对照 CPU 调度、CPU 频率和可获得的热状态。Android 12 起可在支持的设备和渲染场景用 Perfetto FrameTimeline 区分应用与 SurfaceFlinger 的帧超期。`dumpsys gfxinfo <包名> framestats` 可补充指定应用的近期帧数据，其覆盖范围取决于渲染方式。[Perfetto FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline) · [Android dumpsys](https://developer.android.com/tools/dumpsys#ui)
- **电脑发命令慢**。用低频的 `adb -s <传输标识> shell true` 测端到端耗时，同时记录成功、超时、掉线和样本数。该耗时包括电脑启动进程、ADB 传输和手机执行 shell。可以在独立重复轮次运行探针，保留空闲组的原始负载。帧时间平稳而命令耗时升高时，优先查 ADB 路径。只有两类数据和操作时刻对得上并能复现，才进一步检验具体原因。

## 第一版范围

1. 在 `adbpilot` 内增加按需诊断模块，复用 [`AdbClient.run`](../../adbpilot/client.py#L47)。用单调时钟记录命令耗时，采集开始时确认并固定目标传输。显式指定 USB 或 Wi-Fi 时，从未去重的列表确认目标，断线时保留已采集结果和缺失原因。
2. 先提供 CLI 短时采集和本地 JSON 摘要。记录传输类型、Android/ADB 版本、命令耗时、错误、样本数及可用的帧数据。采样串行、低频、限时，默认只保存摘要。机型或权限限制导致的空数据标为不可用，短采样以中位数和最大值为主。
3. 手机帧卡顿可复现时，再接入短时 Perfetto 采集与导出。采集结束后拉取 trace，避免传输影响同一轮测量。设备端追踪能力按机型和系统版本探测，并保留离线 trace 导入路径。CLI 的采集结果和额外负载通过真机验证后，再考虑 GUI 入口。

首轮验证应覆盖单设备 Wi-Fi、同一设备 USB/Wi-Fi 双传输，以及中途断线。验收以能区分命令慢与画面掉帧、数据缺失可识别、采集开关对结果的影响可测为准。
