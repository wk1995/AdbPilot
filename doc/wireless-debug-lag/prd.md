# 无线调试卡顿诊断 PRD

2026-11-11 · 设计稿 · [可行性分析](feasibility.md) · [技术方案](technical-design.md)

## 问题与目标

Android 开发者在无线调试时感到卡顿，需要判断是手机上滑动、动画或触摸反馈变慢，还是电脑发出的 ADB 操作变慢。打开调试开关、建立空闲连接、运行 AdbPilot、持续传输数据都可能改变条件，用户目前需要手动记录并拼接证据。

在 AdbPilot 增加短时诊断。用户选择连接、复现动作、保存本地报告，再用同一台手机做对照。报告说明哪些指标发生了变化、在哪个场景发生、数据覆盖到哪里。无线 ADB 是待验证变量，卡顿原因需要真机复现和对照支持。

## 开源方案与取舍

| 参考项目 | 可借鉴的做法 | AdbPilot 的采用方式 |
| --- | --- | --- |
| Android Dev Monitor | 无线连接延迟检查、Perfetto 和帧诊断、会话打点及对比 | 借鉴“采集一次、记录卡顿时刻、和基线比较”的流程。首版放进现有 CLI，保留设备选择和连接状态。 [项目说明](https://github.com/marko69420/android-dev-monitor#whats-new-in-v250) |

| Perfetto | 手机端录制系统调度和帧时间，电脑端打开 trace | 直接复用系统跟踪。真机基线可以在无线调试关闭时从手机录制。 [真机系统跟踪](https://developer.android.com/topic/performance/tracing/on-device) · [FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline) |

## 使用流程

1. 在同一台手机、同一 App 或系统页面，确定一个可重复的动作。记录网络、充电状态、刷新率和同时运行的调试工具。
2. 用手机本地 System Tracing 录一次关闭无线调试的基线。再分别录制开启但未连接、普通 ADB 已连且空闲、AdbPilot GUI 空闲、实际调试操作五种条件中的相关组别。实时日志、APK 安装、文件传输、投屏每次只加一项。[对照组操作](feasibility.md#真机对照)
3. 在已连接的条件下，用 CLI 采集 30 秒 ADB 响应数据，复现时按需打点。可指定应用读取近期帧数据。要保留真实的空闲条件时，把 ADB 探针放在另一次重复试验。
4. 比较两份本地报告，查看 ADB 命令耗时和失败、可用的帧数据、用户打点和对照限制。手机端 trace 可以在 Perfetto UI 打开，查看整机或目标应用的帧时间。 [Perfetto UI](https://perfetto.dev/docs/visualization/perfetto-ui)

## 首版需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| R1 | 通过 CLI 显式启动会话。默认 30 秒，使用当前 ADB 配置。多条在线传输时要求明确选择 USB 或 Wi-Fi 对应的 ADB 标识。 | 同一手机同时在线时可分别采集。目标消失或明确变化后停止当前会话，保留已取得的样本。 |
| R2 | 以低频短命令测量主机到设备的 ADB 命令耗时，记录成功样本的中位数、最大值、超时、失败及样本数。用户可用 Enter 标记感到卡顿的时刻。 | 输出标为“ADB 命令耗时”，含单位和采样窗口。卡顿标记可定位到会话内时间。 |
| R3 | 指定应用时补充近期 HWUI 帧样本，显示帧耗时、覆盖范围和采集状态。给出手机端 trace 的录制与查看路径。 | 能解析时显示近期帧证据。无帧、系统限制、格式异常或窗口发生变化时显示明确状态。整机和其他渲染场景通过 trace 进一步确认。 |
| R4 | 保存本地结构化报告，可离线比较同一设备两次采集。 | 报告显示两边的指标、样本量及差值。对照条件或数据口径不一致时明确标注，对应指标仅并排展示。离线对照不要求安装 ADB。 |
| R5 | 默认采集范围有限，设备或链路异常时保留可用结果。 | 单次会话内探针串行，超时和取消有界。摘要只写用户选择的路径，省略原始设备标识、IP、日志与命令原始输出。 |

首版验收环境为 Android 11+ 已授权的真机和现有 Windows、macOS CLI。Linux 进行 CLI 回归验证。至少覆盖一台 Android 11 和一台 Android 12+ 设备，优先包含实际复现卡顿的机型。以上是验收目标，尚无实测数据。

## 验收场景与后续范围

- **ADB 命令变慢**。已知延迟或超时能在相应时间出现，手机帧证据独立显示。报告保留可复现的差异和证据缺口。
- **手机画面掉帧**。手机本地 trace 能看到帧时间变化。命令样本正常时，报告保留这两条观测，便于继续查看应用或系统调度。
- **数据不足**。掉线、空闲无帧、第三方渲染、近期窗口过短及不匹配的报告都有可理解的提示。数值缺失用空值表示。
- **采集干扰**。同一场景交替做无探针和有探针的复现，比较手机帧指标和用户感受。若干扰可重复出现，降低采集频率或把 ADB 探针与帧记录安排在独立轮次。

真机证据支持后，第二阶段再做 AdbPilot 一键录制、导出 Perfetto trace 和可选的本地 Trace Processor 分析。GUI 入口排在 CLI 采集与对照验收之后。持续监控、常驻手机端、云端上传和自动判定根因留在首版范围之外。
