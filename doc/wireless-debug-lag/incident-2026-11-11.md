# 2026-11-11 手机卡死记录

当前分支能记录单条 ADB 传输的超时。遇到这次手机本机卡死、USB 和 Wi-Fi 同时无响应的情况，仍需人工测量各链路并在重启后补查系统记录。卡死前的设备状态和根因未能采到。见 [手机卡死诊断优化方案](freeze-diagnostics-design.md)。

## 卡死时的连接和操作

- 手机型号为 `2410DPN6CC`，电脑为 Mac，Platform-Tools 版本为 `37.0.0`。
- 手机同时插着 USB 并开启 Android 无线调试。ADB 列表显示同一台手机有一条 USB 传输和两条 Wi-Fi 传输。
- 用户确认当时开启了小米互联服务，并在「当前设备」下通过「妙想桌面」从 Mac 控制手机。
- 卡死时，手机本机也无法操作。

## 现场测量

| 检查 | 卡死时的结果 |
| --- | --- |
| `adb devices -l` | 三条手机传输都显示 `device` |
| `adb shell true` | USB 和两条 Wi-Fi 各试 3 次，9 次均在 3 秒内未返回 |
| USB 读取 CPU、温控和前台应用 | 均超时 |
| USB `exec-out` | 简单的 `echo` 命令也超时 |
| Mac 上的 ADB server 和本机模拟器 | `host-features` 约 115 ms 返回，模拟器 `shell echo` 约 159 ms 返回 |

## 恢复后

手机重启并关闭无线调试后，只剩 USB 连接。5 次 `adb shell true` 均成功，耗时为 33.9、39.7、47.4、52.4 和 68.9 ms。CPU、温控信息恢复可读，温控状态为 `0`。

手机日志中的本次 `SYSTEM_BOOT` 时间为 `2026-11-11 14:55:56`。`sys.boot.reason` 与 `ro.boot.bootreason` 均为 `reboot`。查看到的系统记录中没有对应的 watchdog 或 `system_server` 崩溃条目。

恢复期间同时发生了重启和关闭无线调试。小米互联服务及妙想桌面的恢复后状态未记录。现有数据能确认手机本机失去响应时，USB 和 Wi-Fi 上的 ADB 命令也同时超时。各功能的单独影响和叠加影响仍待同机对照。
