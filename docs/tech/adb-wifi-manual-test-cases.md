# ADB Wi-Fi 人工测试用例

这些用例需要真实手机、电脑和网络，不能用单元测试代替。每条用例记录主机系统、adb 路径、`adb version` 里的 Platform-Tools revision、手机系统，以及结果。

没有报出 `mdns_service_version: 2.0` 的设备时，2.0 相关用例记为「未验证」，不能记为通过。

## 准备

- 手机：Android 11 或更高，已打开开发者选项和无线调试。
- 电脑：AdbPilot 能找到一份 adb。建议再准备一份 34.0.5 以下的旧 adb，用来确认旧版本不会在软件里配对。
- 手机和电脑先连同一个 Wi-Fi。配对页面和无线调试主页要同时能打开，因为两个地址的端口不同。

这份文档是用例正文的唯一来源。`docs/test-board/index.html` 读取这里的「用例」表，不另存一套用例。结果写在「结果」表；「记录」只补充某一次测试的经过。

## 用例

| 编号 | 分组 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| M1 | 能力 | 打开无线调试，点击「检查能力」 | 显示当前 adb 路径和能力。版本达到 34.0.5 才显示安全配对可用。只有版本、发现设备功能都满足时，才显示主机具备 Wi-Fi 2.0 条件 |
| M2 | 能力 | 把 adb 换成 34.0.4 或更旧，再点「检查能力」，然后尝试配对 | 提示升级。软件不执行配对。按地址连接仍可使用 |
| M3 | 配对 | 在手机「使用配对码配对设备」页面取出地址和六位码，在软件中配对，连接地址留空 | 配对成功。设备自动出现时，状态为已出现；没有出现时，提示改填无线调试主页上的连接地址，且不要求重新输入配对码 |
| M4 | 配对 | 重复 M3，但提前填入无线调试主页上的连接地址 | 设备没有自动出现时，软件用这个地址连上。状态与「自动出现」不同 |
| M5 | 配对 | 故意把配对地址填进连接地址 | 连接失败，并提示不要使用配对端口 |
| M6 | 配对 | 输入错误或过期的六位码 | 提示重新生成配对码。输出和进程参数里看不到这六位数字 |
| M7 | 配对 | 打开配对码页面后立刻关闭，再提交刚才的地址 | 提示配对页面已关闭或地址变化，不显示为已配对 |
| M8 | 配对 | 配对成功后断开，手机和电脑仍在同一网络，再次打开软件并点「连接已配对」 | 已记住这台电脑的手机可以再次连上，不需要重新输入六位码 |
| M9 | 配对 | 点「扫码配对」，用手机「使用二维码配对设备」扫描电脑上的二维码 | 方向是手机扫电脑。成功后设备出现。关闭窗口会取消等待 |
| M10 | 能力 | 手机连上已勾选「始终允许」的网络后，查看能力 | 只有 `adb mdns track-services --proto-text` 报出不低于 2.0 时，才显示设备支持 Wi-Fi 2.0。系统版本是 17 但没有该字段时，仍显示安全无线调试 |
| M11 | 网络 | 电脑和手机不在同一网络，或使用会隔离设备的企业 Wi-Fi | 不把这种情况标成软件故障。提示确认同一网络，并允许手输连接地址 |
| M12 | 命令行 | 命令行执行 `adbpilot pair <配对地址>`，按提示输入六位码 | 配对码不出现在命令本身。结果与界面同一套状态。失败时命令退出码为 2 |
| M13 | 设备 | 电视或 Wear OS | Android 13 及以上按 M3 验证。Android 11 的手表只确认提示不适用，不要求配对成功 |
| M14 | 路径 | 点路径框下拉箭头 | 列出电脑上已找到的 adb，以及以前浏览或下载过的路径。选中后，下一次操作改用这一份 |
| M15 | 下载 | 点「下载版本」，确认默认目录，再点「打开目录」 | 源码运行时目录是项目目录。打包后的程序目录是应用所在目录。系统文件窗口打开的是这个目录 |
| M16 | 下载 | 选择 34.0.4，点「下载并使用」 | 窗口显示进度条和百分比，日志不被进度刷满。完成后路径切到 `tools/platform-tools-34.0.4/platform-tools/adb`，并出现在下拉里 |
| M17 | 下载 | 不改目录，再次下载同一个 34.0.4 | 不再重新下载，直接提示已在目录中，并继续使用这份 adb |
| M18 | 下载 | 把目录改到别处，下载另一个版本 | 文件保存到新目录。回到默认项目目录时，原先下载的版本仍在 |
